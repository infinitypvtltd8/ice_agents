BUILD: DETERMINISTIC ARXIV CITATION EXTRACTOR & ELSEVIER XML GENERATOR
Build a production-ready desktop/web application for processing arXiv preprint citation packages and generating XML in the required Elsevier ANI-style structure.
1. FUNDAMENTAL REQUIREMENT — NO AI DURING PRODUCTION PROCESSING
AI may be used ONLY while developing this application.
Once the application is built, normal citation processing MUST NOT use:
OpenAI
Gemini
Claude
Copilot APIs
LLM APIs
AI agents
embeddings APIs
AI OCR APIs charged per token/request
generative AI classification
generative AI extraction
external AI inference services
There must be ZERO AI-token/AI-credit consumption when processing production files.
The production processing pipeline must be deterministic and based on:
document parsing
coordinate/layout extraction
OCR only where required
regex/pattern matching
dictionaries
deterministic parsers
configurable rule engine
cross-document comparison
XML templates/builders
XSD/schema and business-rule validation
human review where a rule cannot safely resolve an ambiguity
Do NOT secretly add an LLM fallback.
If deterministic processing cannot confidently resolve something, FLAG/HOLD it for human review instead of guessing.

envelope symbol

REFERENCES
Source:

Possible headings:

39. HOLD OVERRIDE, FULL XML EDITING & FORCED GENERATION
The application MUST allow the operator to generate, edit, validate, override, and export XML even when the article contains HOLD items.
A HOLD is a warning/review state. It must NOT permanently prevent XML generation.
XML GENERATION WHILE ON HOLD
When extraction and rule processing are complete, generate the FULL XML using all metadata that has been successfully extracted.
If one or more fields are on HOLD:
still generate the complete XML preview
clearly identify the metadata/XML elements affected by the HOLD
highlight unresolved fields
show the HOLD reason
show the rule that created the HOLD
allow the operator to manually correct the affected data
allow the operator to override the HOLD
allow XML regeneration after correction/override
The user must never be forced to restart processing simply because a HOLD occurred.

HOLD MANAGEMENT
Each HOLD must provide these actions:
EDIT DATA
Edit the extracted metadata responsible for the HOLD.
VIEW EVIDENCE
Open the exact PDF/support-document evidence that caused the HOLD.
ACCEPT EXTRACTED VALUE
Accept the system's existing value despite the warning.
OVERRIDE HOLD
Allow an authorized user to manually clear/override the HOLD.
KEEP HOLD
Leave the warning unresolved while continuing to inspect the article/XML.
After an override, record:
original HOLD reason
rule ID
original extracted value
final accepted/edited value
user action
timestamp
optional override reason
Never delete the original HOLD information from the audit trail.

43. FORCE GENERATE / FORCE EXPORT
Provide authorized users with:

and, if business workflow permits:

Before export, display:
"3 unresolved HOLD items remain."
Show each HOLD.
The user can then:

continue with authorized export
Do NOT silently remove HOLD warnings simply to make the article appear completed.

45. ARTICLE STATUS MODEL
Use separate processing statuses instead of treating HOLD as a fatal error.
Suggested statuses:
UPLOADED
EXTRACTING
EXTRACTED
REVIEW REQUIRED
ON HOLD
MANUALLY EDITED
HOLD OVERRIDDEN
XML GENERATED
XML MANUALLY MODIFIED
VALIDATION FAILED
VALIDATED
READY FOR EXPORT
EXPORTED
A document can therefore be:
XML GENERATED + ON HOLD
or:
XML GENERATED + HOLD OVERRIDDEN
A HOLD must not automatically mean that XML generation failed.

46. CRITICAL PRINCIPLE
The rule engine ASSISTS and CONTROLS automated processing, but the authorized human operator retains final control.
Therefore:
RULE ENGINE
→ detects problems
HOLD
→ warns the operator
HUMAN REVIEW
→ resolves/overrides problems
XML GENERATOR
→ remains available
XML EDITOR
→ allows final correction
VALIDATOR
→ checks technical correctness
AUDIT LOG
→ records what happened
The system must NEVER trap an article because a deterministic rule produced a HOLD.
The goal is controlled human override with complete traceability — not an inflexible automated pipeline.
